# 动态线性约束引擎

在有限域 F_p（p = 1000000007）上维护一组形如 `x_v − x_u ≡ d` 的方程，支持随时添加、删除方程，
并回答"`x_v − x_u` 是多少 / 无法确定 / 整个系统矛盾"。

- 时间 **O(n + q log n)**（均摊），空间 **O(n + q)**
- C++20，只依赖标准库
- 三个互相独立的实现互相校验

## 使用

```sh
make                                   # 编译全部程序到 build/
build/solver < examples/sample.in      # 从标准输入读题，向标准输出写答案

make test        # 单元测试 + 样例 + 短时随机差分测试（数秒）
make fuzz        # 完整随机差分测试（约 15 秒），可加 SEED=...
make sanitize    # 在 AddressSanitizer / UBSan / 边界检查下重跑测试
make mutation    # 变异测试：向求解器植入 25 个错误，检查测试能否全部发现（数分钟）
make bench       # n, q 达到 200000 的性能测试：时间、内存、交叉校验
```

输入格式见题面：首行 `n q`，随后 q 行 `+ id u v d`、`- id`、`? u v`。
`id` 可以是任意 64 位整数。输入不合法时程序报错退出，而不是给出错误答案。

## 核心思路

1. **方程组就是一张图。** 变量是顶点，方程 `x_v − x_u = d` 是一条从 u 到 v、带"增益" d 的边。
   - 系统有解 ⟺ 沿任何一个环走一圈，增益之和为 0；
   - `x_v − x_u` 被唯一确定 ⟺ u 与 v 连通，其值就是任意一条路径上的增益之和。
2. **删除被"时间"吸收。** 整个操作序列事先已知，所以每条约束在加入时就知道自己何时"到期"。
   问题于是变成只增不减的：没有任何东西需要被撤销。
3. **按到期时间的最大生成森林。** 新边若连接两棵树，直接加入；若闭合了一个环，就丢掉环上
   **最早到期**的那条边。于是森林里任意两点间的路径，总是所有路径中"活得最久"的那一条。
4. **矛盾是一个时间点。** 如果闭合的环增益之和非零，那么在环上最早到期的边到期之前，系统
   都是矛盾的。整个"矛盾状态"只需要一个整数 `contradictory_until`。

查询在时刻 t 的回答：`t < contradictory_until` → `CONTRADICTION`；否则若森林路径存在且尚未到期 →
路径增益；否则 `UNKNOWN`。主循环全文见 `src/solver.hpp`（约 30 行）。

## 文件

| 路径 | 内容 |
|---|---|
| `src/solver.hpp` | 算法本体：到期时间的预处理 + 主循环 |
| `src/spanning_forest.hpp` | 按到期时间的最大生成森林（link-cut tree），对外只有 `insert` 和 `path` |
| `src/problem.hpp`, `src/cli.hpp`, `src/main.cpp` | 题目的数据类型、文本读写、命令行外壳 |
| `verify/brute.hpp` | **暴力基准**：每次查询都把当前方程写成稠密矩阵，在 F_p 上做高斯消元。完全不知道"图"的存在 |
| `verify/rollback.hpp` | **第二个快速实现**：对时间分治 + 可撤销的带权并查集，O(q log q log n)。用于在暴力无法到达的规模上交叉校验 |
| `tests/unit_tests.cpp` | 23 个手算答案的用例（三个实现都要通过）、非法输入、森林接口契约 |
| `tests/fuzz.cpp`, `tests/workloads.hpp` | 随机差分测试与各类操作序列生成器 |
| `tests/mutation.sh` | 变异测试 |
| `tests/gen.cpp`, `bench/` | 大规模输入生成、时间与内存测量 |

三个实现只共享文本读写层（`problem.hpp`）；对操作含义的全部解释、取模、求解逻辑各写各的。

## 实测结果

环境：4 核 Intel Xeon 2.1 GHz，g++ 13.3 `-O2`。时间为 3 次运行中最快的一次，包含读入与输出文本；
内存为内核报告的峰值常驻内存。不同次运行之间有约 ±20% 的波动。

**正确性**

- 单元测试：23 个用例 × 3 个实现全部通过；9 种非法输入全部被拒绝。
- 随机差分测试（每个种子）：约 24 万组小数据（510 万次操作）与暴力基准、第二实现逐一比较；
  另有约 1900 组大数据（1880 万次操作）与第二实现比较。两个种子均无任何不一致。
- 上述测试在 AddressSanitizer + UBSan 下同样通过。
- 变异测试：植入的 25 个错误全部被发现（单元测试与随机测试各自都能独立发现全部 25 个）。

**性能**（`make bench`，q = 200000）

| 操作序列 | n | solver 秒 | solver MiB | rollback 秒 | rollback MiB |
|---|---:|---:|---:|---:|---:|
| 随机增 / 删 / 查 | 200000 | 0.084 | 23.9 | 0.123 | 18.1 |
| 随机增 / 删 / 查 | 20000 | 0.195 | 13.0 | 0.133 | 15.3 |
| 随机增 / 删 / 查 | 500 | 0.121 | 12.1 | 0.112 | 15.0 |
| 先进先出删除（每个环都换边） | 20000 | 0.166 | 12.1 | 0.131 | 13.9 |
| 后进先出删除 | 20000 | 0.225 | 12.1 | 0.106 | 13.9 |
| 只增不删 | 50000 | 0.250 | 15.0 | 0.110 | 21.1 |
| 长链反复断开再接上 | 100000 | 0.151 | 19.1 | 0.133 | 20.9 |
| 长链 + 10 万次查询 | 100000 | 0.186 | 19.1 | 0.101 | 21.0 |
| 矛盾反复出现与消失 | 100000 | 0.167 | 19.2 | 0.091 | 21.0 |
| 专门针对 rollback 的最坏情形 | 65536 | 0.190 | 17.5 | 0.175 | 18.8 |

所有输入上两个实现的输出逐字节相同。完整表格（含 q 从 2.5 万到 80 万的倍增序列）由 `make bench` 打印。

**如实说明：** 主求解器的渐近复杂度更好（每次操作 O(log n)，对照实现是 O(log q · log n)），
但在题目规模上它并不更快——端到端计时，稀疏输入上快约 1.3–1.5 倍，稠密输入上慢约 1.5–2.3 倍
（只计求解本身、不计读写文本，最多慢约 3 倍）。原因是并查集的内层循环极其紧凑，多出的 log 因子被
小常数抵消了；把规模放大到题目上限的 16 倍，这个结论也没有改变。如果只关心运行时间，`build/rollback` 同样可用。

## 限制

- **离线算法**：需要先读完全部操作，才能知道每条约束何时被删除。若删除时刻在加入时就已知
  （例如带有效期的约束），主求解器可以逐条在线处理；完全在线的版本没有实现。
- 时间戳用 `int` 表示，操作数须小于 2³¹ − 1（题目上限为 200000）。
