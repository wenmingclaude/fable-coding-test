# 正确性与复杂度

本文区分三种不同强度的断言，并在每处标明属于哪一种：

* **【定理】** 有完整数学论证的命题，论证写在本文里；
* **【依赖】** 论证成立所依赖的、本文没有证明的前提；
* **【经验】** 只由测试支持的陈述。测试通过不是证明。

核心结构是：

> 求解器的正确性**不需要被整体证明**。它每次运行都交出一份证书，
> 证书由一个小得多的程序检查。只要检查器正确，被接受的答案就正确——
> 不管求解器内部有没有 bug。

所以第 1–3 节（检查器）是整个系统真正的可信基础；第 4–6 节（求解器）解释的是
"为什么求解器总能交出合格的证书"，其中的任何疏漏都只会导致**证书被拒绝**，而不会导致**错误答案被接受**。

## 1. 记号

* 赋值 σ：给每个变量一个真值。文字 `l` 在 σ 下为真或为假。
* 子句：文字的析取。空子句 ⊥ 在任何赋值下为假。σ 满足子句 `C` ⟺ `C` 中至少一个文字为真。
* 公式 `F`：子句的合取。σ 满足 `F` ⟺ σ 满足其中每条子句。
* `F ⊨ C`（`F` 蕴含 `C`）：每个满足 `F` 的赋值都满足 `C`。
* `F ≡ G`（等价）：满足 `F` 的赋值与满足 `G` 的赋值完全相同。

两个立即可得的事实：

* (E1) 若 `F ⊨ C`，则 `F ∧ C ≡ F`。**加入一条推论，或者把它再删掉，都不改变解集。**
* (E2) 若 `F ⊨ ⊥`，则没有赋值满足 `F`（因为没有赋值满足 ⊥）。

## 2. SAT 证书：直接代入

**【定理 2.1】** 若 `model_check` 接受，则 `F` 可满足。

论证：检查器读入 `F` 和一组文字，核对 (a) 每个变量 1..n 恰有一个值，(b) 每条子句至少含一个为真的文字。
这正是"σ 满足 `F`"的定义。∎

这里没有任何推理，只有求值；它完全不依赖求解器是如何找到 σ 的。

## 3. UNSAT 证书：RUP 证明

规则的完整陈述在 [PROOF_FORMAT.md](PROOF_FORMAT.md) §3。这里证明它是可靠的。

**【引理 3.1（单位传播是可靠的）】** 设 σ 满足子句集 `D`，且 σ 使文字集合 `A` 中的文字全为真。
则从 `A` 出发在 `D` 上做单位传播，(i) 推出的每个文字在 σ 下为真；(ii) 不会遇到冲突。

论证：对传播步数归纳。设到目前为止推出的文字在 σ 下都为真。下一步用到子句 `C ∈ D`，
它除 `l` 外的文字都已被赋为假，即它们的否定在 σ 下为真，所以这些文字在 σ 下为假。
σ 满足 `C`，故 `l` 在 σ 下为真——(i) 成立。若某条子句所有文字都被赋为假，它在 σ 下也全假，
与 σ 满足 `D` 矛盾——(ii) 成立。∎

**【定理 3.2（RUP 步骤是可靠的）】** 设从"`C` 的每个文字为假"出发在 `D` 上做单位传播遇到冲突。则 `D ⊨ C`。

论证（反证）：若有 σ 满足 `D` 而不满足 `C`，则 `C` 的每个文字在 σ 下为假，即出发点的每个文字在 σ 下为真。
由引理 3.1(ii) 不会遇到冲突，矛盾。∎

**【定理 3.3（检查器的不变量）】** 检查器处理证明的任意前缀之后，`DB` 中每条子句、`T` 中每个文字都被 `F` 蕴含。

论证：对步骤归纳。
* 初始：`DB = F`（去掉重言式与重复文字是等价变换）。`T` 由空赋值出发传播得到，对任何满足 `F` 的 σ
  应用引理 3.1(i)（取 `A = ∅`），`T` 中文字在 σ 下为真。
* 添加 `C`：RUP 检查从 `T ∪ ¬C` 出发。任取满足 `F` 的 σ；由归纳假设 σ 满足 `DB` 且使 `T` 全真。
  若 σ 不满足 `C`，则出发点全真，由引理 3.1(ii) 不会冲突——与检查通过矛盾。故 σ 满足 `C`，即 `F ⊨ C`。
  之后扩充 `T` 同初始情形。
* 删除：`DB` 变小，`T` 不变，"每个成员被 `F` 蕴含"显然保持。∎

**【定理 3.4（被接受的证明确实证明了 UNSAT）】** 若 `rup_check` 输出 `s VERIFIED`，则 `F` 不可满足。

论证：接受意味着某一时刻从 `T` 出发在 `DB` 上传播遇到冲突。若有 σ 满足 `F`，由定理 3.3 σ 满足 `DB` 且使 `T` 全真，
由引理 3.1(ii) 不会冲突。矛盾。∎

带 `--assume` 时把定理中的 `F` 换成 `F ∧ a₁ ∧ … ∧ a_k` 即可（检查器只是多加了几条单位子句）。

### 3.5 为什么检查器不需要信任求解器

定理 3.4 的前提里**没有出现求解器**。它对任意一个文件成立：求解器写的、有 bug 的求解器写的、
恶意构造的、随机字节。检查器的输出只取决于 `F` 和文件内容。
求解器的搜索策略、数据结构、内存管理都不在可信范围内。

对应地，检查器必须防止的错误只有一种：**接受了不该接受的证明**（拒绝合法证明只是不便，不是不可靠）。
代码上的防线：

1. 每一条引理都检查，没有"抽查"或"信任标记"；
2. 证明中的记号严格解析，越界变量、非整数、未结束的行都拒绝；
3. RUP 检查的临时假设在检查后全部撤销（`hasRup` 末尾的循环），不会泄漏到后续步骤；
4. 删除只缩小 `DB`（§PROOF_FORMAT 3.4），因此删除相关的任何实现错误只可能使检查更严格；
5. 检查器自己读取 `F`，不接受求解器转述的公式。

### 3.6 仍然必须信任什么

**【依赖 D1】** `checker/rup_check.cpp`（362 行）与 `checker/cnf.hpp`（168 行）的实现符合 §3 的规则。
这一点没有形式化验证。缓解手段：(a) 另有一份朴素的 Python 实现 `checker/rup_check.py`（单位传播靠反复全表扫描，
没有监视文字），测试组 E 在数千份合法的和被破坏的证明上要求两者结论一致；(b) 对可满足的公式提交各种"差一点就对"的证明，
要求全部拒绝；(c) 变异测试向证明检查器植入 9 种 bug（8 种使它接受非法步骤，1 种使它过严），全部被测试发现（数据见 RESULTS.md）。
格式是标准的 DRUP，原则上可交给第三方检查器（如 drat-trim）复核，但本次环境中没有实际运行第三方工具。

**【依赖 D2】** 检查器读到的公式就是用户想问的公式（解析正确）。三个独立读取器的一致性由测试组 G 检查。

**【依赖 D3】** 编译器、标准库、硬件、操作系统正确。

**【依赖 D4】** `model_check` 的实现符合定理 2.1 的描述（约 100 行，同样有 Python 侧的独立代入检查）。

## 4. 求解器的不变量

以下解释求解器为什么能交出合格证书。记 `F` 为输入公式，`Φ` 为求解器当前的子句库（原始子句 + 学习子句），
`U₀` 为第 0 层（无任何决策时）被赋值的文字集合。

**(I1) 子句库只含推论。** `Φ` 中每条子句被 `F` 蕴含；`U₀` 中每个文字被 `F` 蕴含。

**(I2) 不丢失约束。** `Φ ∧ U₀ ⊨ F`。即：凡是满足当前子句库并且与第 0 层文字一致的赋值，都满足原公式。

**(I3) 赋值轨迹。** 轨迹上每个文字要么是决策（猜测，不带理由），要么带一条原因子句 `R ∈ Φ`：
该文字在 `R` 中，`R` 的其余文字都为假且在轨迹上更靠前。

**(I4) 监视不变量 (W)。** 对每条长度 ≥ 2 的子句：若它的某个监视文字为假，则另一个监视文字为真，
或者那个假文字还在传播队列里等待处理。

**(I5) 证明同步。** 检查器处理完求解器已写出的证明前缀之后，检查器的 `DB ∪ T` 蕴含的单位传播结果
不弱于求解器的 `Φ ∪ U₀`：求解器的每条学习子句都已作为引理写出，每个第 0 层文字要么由 `DB` 单位传播可得，
要么已作为单位引理写出；求解器删除的子句检查器可以保留（保留更多只会更强）。

### 4.1 各类操作属于哪种变换

| 操作 | 性质 | 依据 |
|---|---|---|
| 合并子句内的重复文字 | 等价变换 | `x ∨ x ≡ x` |
| 丢弃重言式子句 | 等价变换 | 恒真子句不约束任何赋值 |
| 单位传播赋值一个文字 | 不改变子句库；该赋值是"当前决策下的必然后果" | 引理 3.1 |
| 决策 | **不是推理**，是猜测；不产生任何被写入证明的东西 | — |
| 加入学习子句 | 加入推论，解集不变 | 定理 4.2 + (E1) |
| 删除学习子句 | 删除推论，解集不变 | (E1) |
| 第 0 层：删除含真文字的子句 | 在 `U₀` 之下等价 | 该子句被 `U₀` 蕴含 |
| 第 0 层：去掉子句中的假文字 | 在 `U₀` 之下等价 | 与 `U₀` 中的单位子句归结 |
| 回退 / 重启 | 只撤销赋值，不改变子句库 | — |
| 改变活跃度、相位、重启时机 | 只影响搜索顺序 | — |

注意"删除**原始**子句"只发生在第 0 层化简中，且被删的子句由 `U₀` 蕴含，所以 (I2) 保持；
学习子句则可以任意删除。

### 4.2 学习子句

**【定理 4.2】** 冲突分析得到的学习子句 `L`（最小化前后均是）满足：(a) `Φ ⊨ L`，从而 `F ⊨ L`；
(b) `L` 相对于 `Φ ∪ U₀` 具有 RUP 性质。

论证 (a)：分析从被证伪的子句 `K₀ ∈ Φ` 出发，每一步与某个文字 `p` 的原因子句 `R_p ∈ Φ` 归结，得到 `K_{i+1}`。
归结是可靠的（若 σ 满足 `(A ∨ x)` 与 `(B ∨ ¬x)`，按 `x` 的真假分情况即得 σ 满足 `(A ∨ B)`），
故每个 `K_i` 被 `Φ` 蕴含。分析中略去第 0 层的假文字，相当于再与 `U₀` 中的单位子句归结。
最小化删去的文字 `q`，其否定可由 `L` 中其余文字的否定经原因子句推出（见下），等价于再做若干次归结。

论证 (b)：把 `L` 的文字全设为假。称分析过程中被归结掉的那些变量在轨迹上的文字为冲突侧文字，
按它们在轨迹上的顺序归纳。冲突侧文字 `p` 的原因子句 `R_p = (p ∨ q₁ ∨ … ∨ q_m)` 中，每个 `q_i` 在求解器当时的赋值下为假，
并且恰好属于以下三种之一：`q_i` 本身就是 `L` 的文字（现在被假设为假）；`q_i` 在第 0 层为假（检查器由 (I5) 已知）；
`¬q_i` 是更早的冲突侧文字（由归纳假设已被传播为真，故 `q_i` 为假）。
于是 `R_p` 成为单位子句，`p` 被传播出来——或者传播更早地遇到了冲突。
全部冲突侧文字就位后，`K₀` 的所有文字为假：冲突。
最小化删去的文字按同样的方式先被传播出来（它们的蕴含锥落在保留文字上；按轨迹顺序取最早被删的文字，
它的锥中不含其他被删文字，归纳即可）。∎

**实现上曾经在这里出过错**：最小化原地压缩学习子句，导致被删文字的 `seen` 标记没有清除，
污染了下一次分析，学出了不是推论的子句。它被两道独立防线同时抓住：与暴力枚举的差分测试（答案错），
以及证明检查器（"lemma 2 is not implied by unit propagation"）。这个 bug 被保留为变异测试中的 `undo-seen`。

### 4.3 回退为什么不会漏掉解

**【定理 4.3】** 求解器的任何操作都不会排除 `F` 的解：在任意时刻，`F` 的每个解都满足 `Φ` 且与 `U₀` 一致。

论证：这就是 (I1)。子句库的变化只有加入推论与删除子句，赋值的变化分两类：
第 0 层的传播（引理 3.1：`F` 的每个解都与之一致）与更高层的赋值。
更高层的赋值依赖于决策，**它们不是断言**——求解器从不声称"`x` 必须为真"，只声称"在当前这组猜测下 `x` 为真"。
回退撤销的正是这些有条件的赋值，因此撤销不会丢失任何关于 `F` 的知识；
而每次冲突留下的学习子句是无条件成立的 `F` 的推论，它排除的只是不满足 `F` 的赋值。∎

换句话说：搜索树上被"剪掉"的分支，是因为存在一条 `F` 的推论被该分支上的赋值证伪，
而这条推论已被写进证明，检查器会亲自验证它确实是推论。

### 4.4 报告 SAT 的依据

**【定理 4.4】** 求解器输出 `s SATISFIABLE` 时，所给赋值满足 `F`。

论证：此时所有变量已赋值，传播队列为空且无冲突。由 (I4)，每条子句若有假的监视文字则另一个监视文字为真；
若两个监视文字都非假，则（全部已赋值）它们为真。故 σ 满足 `Φ`，且与 `U₀` 一致，由 (I2) σ 满足 `F`。∎

该定理依赖 (I2)(I4) 在实现中确实成立——这是**【经验】**层面的；
但结论本身每次都由 `model_check` 依定理 2.1 独立核对，不依赖它们。

### 4.5 报告 UNSAT 的依据

**【定理 4.5】** 求解器输出 `s UNSATISFIABLE` 时 `F` 不可满足，且证明文件能通过 §3 的检查。

论证：UNSAT 只在第 0 层冲突时报告（或输入本身含空子句 / 互补的单位子句）。此时被证伪子句 `K ∈ Φ` 的所有文字的否定都在 `U₀` 中。
由 (I1)，`F ⊨ K` 且 `F` 蕴含 `K` 中每个文字为假，故 `F ⊨ ⊥`。
证明方面：由 (I5) 与定理 4.2(b)，每条引理在写出时通过 RUP 检查；最后检查器的 `T ⊇ U₀`，`K` 在其 `DB` 中（或其传播后果已在 `T` 中），
于是从 `T` 传播遇到冲突，空子句被接受。∎

同样，这个论证依赖实现符合 (I1)(I5)；结论则由 `rup_check` 依定理 3.4 独立核对。

### 4.6 终止性

**【定理 4.6】** 不重启时，求解器在有限步内终止。

论证：令 `k_i` 为第 `i` 层上的文字个数，考虑向量 `(k₀, k₁, …, k_n)`。
一次决策使某个新层从 0 变为正数；一次冲突后回跳到第 `b` 层并追加学习子句的断言文字，使 `k_b` 加一、更深的层清零、更浅的层不变。
两种情况下向量都按字典序严格增大。向量每个分量不超过 `n`，故只能增大有限次。
（该论证只要求"作为原因的子句不被删除"，约简时对被锁定子句的保护保证了这一点。）∎

带重启时，默认配置的终止性依赖"无重启的区间可以任意长"：稳定模式的重启间隔是 Luby 序列 × 1024（无界），
模式阶段长度每轮翻倍，约简间隔线性增长，因此迟早出现一段足够长的无重启区间。
这只是一个存在性论证，给出的界是天文数字，**不是性能保证**。专注模式下基于滑动平均的重启单独使用时没有这样的保证。
实际运行中资源上限（时间、冲突数、内存）到达时输出 `s UNKNOWN`。

### 4.7 假设与冲突核

**【定理 4.7】** `solve(A)` 返回 `UNSAT_ASSUMPTIONS` 与核 `C ⊆ A` 时，`F ∧ ⋀C` 不可满足，
且子句 `⋁_{c∈C} ¬c` 相对于 `Φ ∪ U₀` 具有 RUP 性质。

论证：返回发生在轮到假设 `a` 而 `a` 已为假之时。此刻轨迹上的所有决策都是假设。
`analyzeFinal` 从 `¬a` 出发沿原因子句反向遍历，收集遇到的决策文字 `a_{i1}, …`，令 `C = {a, a_{i1}, …}`。
把 `C` 的文字全设为真：按轨迹顺序归纳，被遍历到的每个文字的原因子句的其余文字要么在第 0 层，要么是被遍历到的更早文字，
故全部被单位传播重现，直到 `¬a` 被传播出来，与假设 `a` 为真冲突。由定理 3.2，`Φ ∪ U₀ ⊨ ⋁¬c`，再由 (I1) `F ⊨ ⋁¬c`。∎

**【定理 4.8（查询之间不污染）】** 任何查询结束后 (I1)(I2) 仍然成立，其中不含任何假设。

论证：假设只以"决策"的身份进入轨迹，从不进入子句库；定理 4.2 的归结推导只使用 `Φ` 中的子句，
因此在假设下学到的子句仍然只被 `F` 蕴含（它们会"记得"假设，但形式是 `¬a ∨ …`，即无条件成立的推论）。
`solve` 返回前回退到第 0 层，撤销所有依赖假设的赋值。∎

核不保证最小。

## 5. 复杂度

设 `n` 为变量数，`|F|` 为输入的文字总数。

| 量 | 界 | 性质 |
|---|---|---|
| 求解时间 | 最坏指数 | SAT 是 NP 完全问题；不存在已知的多项式算法 |
| 鸽巢公式 PHP(n+1, n) | 任何归结反驳的长度为 2^Ω(n)（Haken 1985） | 本求解器的推理都是归结，因此在这族实例上**必然**指数；实测见 RESULTS.md |
| 一次单位传播 | 最坏 O(当前子句库文字总数) | 每条子句每次被访问的代价 ≤ 其长度；实际上远小于此（监视文字） |
| 一次冲突分析 | O(冲突侧原因子句的文字总数) ≤ O(n · 最长子句) | |
| 一次回退 | O(被撤销的文字数 · log n)（堆插入） | |
| 一次约简 | O(学习子句数 · log + 监视表总长) | 每 2000 + 300k 次冲突一次，摊还代价低 |
| 内存 | O(\|F\| + 保留的学习子句) | 约简使保留量约随 √冲突数 增长；二元与 LBD ≤ 2 的子句不删，故无严格上界，由 `--mem-limit` 兜底 |
| 证明长度 | 所有学习子句的长度之和 + 删除行 | 与求解器的工作量成正比 |
| 检查时间 | 最坏 O(引理数 × (\|F\| + 证明长度)) | 对**证明长度**是多项式；每条引理一次单位传播 |
| 暴力枚举 | O(2ⁿ · \|F\| / 64) | 只用于 n ≤ 18 的对照 |

**"寻找难、检查易"的准确含义**：检查的代价相对于*证书的长度*是多项式的。证书本身可以相对于 `n` 呈指数长
（鸽巢公式就必须如此）。UNSAT 是否总有短证书是一个未解决的问题（等价于 NP = coNP）。

**关于平均与最坏**：RESULTS.md 中的所有时间都是在特定实例上的实测值，是【经验】。
它们不构成任何最坏情况保证；同一族中换一个随机种子，时间可以相差一个数量级以上（表中有例子）。

## 6. 测试说明了什么，没说明什么

| 证据 | 强度 |
|---|---|
| 某次运行输出 SAT，且 `model_check` 接受 | 对**这一个实例**是证明（依赖 D2–D4） |
| 某次运行输出 UNSAT，且 `rup_check` 接受 | 对**这一个实例**是证明（依赖 D1–D3） |
| 与暴力枚举在几万个小公式上一致 | 【经验】：求解器在小实例上没有答案错误的迹象 |
| 变形测试、构造性测试通过 | 【经验】 |
| 变异测试杀死率 | 【经验】：测试对*这些*人为 bug 敏感；不代表对所有 bug 敏感 |
| sanitizer 下无报告 | 【经验】：在被执行到的路径上没有检测到内存错误与未定义行为 |

因此本项目能给出的最强保证是**逐实例的**：对求解器实际给出过答案并通过检查的每一个输入，
答案是正确的，且这一点不依赖求解器的正确性。
"求解器对所有输入都正确"则没有被证明——也不需要被证明，因为每次使用时都可以重新检查证书。
