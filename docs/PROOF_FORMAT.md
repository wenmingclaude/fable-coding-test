# 证明格式与检查规则

本文档是求解器与检查器之间**唯一的契约**。检查器只需要实现这里写的东西；
求解器内部如何搜索（决策、学习、重启、删除……）与契约无关。

## 1. 输入：DIMACS CNF

```
c 注释
p cnf <变量数 n> <子句数 m>
1 -3 4 0
...
```

三个独立编写的读取器（`src/dimacs.hpp`、`checker/cnf.hpp`、`tools/cnf.py`）遵循同一套规则，
测试组 G 对它们做一致性比对：

* 记号以空白（空格、制表符、换行、回车）分隔，换行没有特殊含义；子句可以跨行，一行可以有多个子句。
* 以 `c` 开头的记号开始一段注释，直到行尾（头部 `p cnf` 里的 `cnf` 除外）。
* `p cnf n m` 必须出现在第一个子句之前，且只出现一次。
* 子句是若干非零整数后跟一个 `0`；单独的 `0` 是**空子句**（恒假）。
* 文字的绝对值不得超过 `n`。没出现过的变量是合法的，可以任意取值。
* 重复文字、重言式子句（同时含 `x` 和 `-x`）、重复子句都是合法输入。
* 以下情况一律**报错退出**，而不是猜测：缺少头部、文字越界、最后一个子句没有 `0` 结尾、
  实际子句数与头部不符、出现非整数记号。猜错输入就等于回答了另一个问题。

## 2. 输出

```
s SATISFIABLE            退出码 10
v 1 -2 3 ... 0           可分多行，必须给出全部 n 个变量的取值

s UNSATISFIABLE          退出码 20；配合 --proof 生成证明文件

s UNKNOWN                退出码 0；达到时间 / 冲突 / 内存上限时
```

## 3. 证明文件

用 `./build/sat_solver --proof out.rup formula.cnf` 生成。文本格式，每个记号规则同上：

```
<文字> <文字> ... 0        添加一条子句（"引理"）
d <文字> <文字> ... 0      删除一条子句（提示）
```

这就是 SAT 竞赛使用的 **DRUP** 格式（DRAT 的子集：所有添加步骤都只用 RUP 规则，不使用 RAT）。
加上 `--proof-no-deletions` 则只输出添加行，即纯粹的 RUP 子句添加序列。

### 3.1 检查器的状态

检查器维护两样东西：

* `DB`：一个子句多重集；
* `T`：一个文字集合（"已确定为真的文字"）。

**不变量：`DB` 中每条子句、`T` 中每个文字，都是输入公式 `F` 的逻辑推论**
（任何满足 `F` 的赋值都满足它们）。

### 3.2 单位传播

给定一个部分赋值，反复执行：若某条子句的文字除一个以外全为假、剩下那个未赋值，
则把剩下那个文字设为真。直到不再有变化，或者出现一条**所有文字全为假**的子句——这称为**冲突**。

单位传播的每一步都是必然的：子句要成立，而其余文字都已为假，剩下的只能为真。
它的结果与扫描顺序无关（能推出的文字集合唯一；只要某个顺序遇到冲突，任何顺序都会遇到）。

### 3.3 规则

| 步骤 | 检查器做什么 |
|---|---|
| 初始化 | `DB := F`（去掉重言式、合并重复文字）；`T :=` 从空赋值出发做单位传播得到的文字。 |
| 添加 `C` | **RUP 检查**：以 `T` 加上"`C` 的每个文字都为假"为起点，在 `DB` 上做单位传播，**必须遇到冲突**；否则拒绝整个证明。通过后 `DB := DB ∪ {C}`，再从 `T` 出发做单位传播，把新推出的文字并入 `T`。 |
| 删除 `d C` | 若 `DB` 中有与 `C` 文字集合相同的子句，移除其中一条；没有则忽略。`T` 不变。 |
| 接受 | 当且仅当某一时刻从 `T` 出发的单位传播遇到冲突——即空子句通过了 RUP 检查。之后的内容不再读取。 |

求解器总会在结尾显式写出空子句 `0`。若它在更早的时刻已经可由单位传播得到，检查器同样接受。

三个细节：

* 引理若是重言式，直接接受但不加入 `DB`（它恒真，永远不会参与传播）。
* 引理若含有 `T` 中的文字，直接接受（"假设它为假"立刻与 `T` 矛盾）。
* 证明中出现 `> n` 的变量、非整数记号、未以 `0` 结束的行，一律视为格式错误并拒绝。

### 3.4 为什么删除行不需要被信任

删除只会让 `DB` 变小。`DB` 越小，单位传播能推出的东西越少，RUP 检查越难通过。
所以删除**永远不会让一个本该被拒绝的证明被接受**；它只是告诉检查器"这条以后用不到了，可以不再扫描它"，
用来让检查速度跟得上求解器（求解器自己也在删除这些子句）。
`rup_check --ignore-deletions` 会忽略所有删除行，结论不变，只是更慢；测试中两种模式都验证。

`T` 在删除后不收缩，同样只依赖不变量：`T` 中的文字是 `F` 的推论，这件事不会因为之后丢掉某条子句而改变。

### 3.5 带假设的查询

`--queries` 模式下，同一个证明流贯穿所有查询。当求解器回答
"在假设 `a₁ … a_k` 下不可满足，冲突子集为 `C = {c₁ … c_j}`"时，它会向证明流写入子句
`(¬c₁ ∨ … ∨ ¬c_j)`——这条子句本身是 `F` 的推论。

验证方法：`rup_check --assume "c₁ … c_j" formula.cnf proof`。
该选项等价于在 `F` 上追加单位子句 `c₁, …, c_j` 后检查同一个证明：
`(¬c₁ ∨ … ∨ ¬c_j)` 一加入，单位传播立刻冲突。

注意两种结论的区别：

| 求解器输出 | 含义 | 证明证明了什么 |
|---|---|---|
| `s UNSATISFIABLE` | `F` 本身无解 | 从 `F` 推出空子句 |
| `s UNSATISFIABLE UNDER ASSUMPTIONS` + `a c₁ … c_j 0` | `F ∧ c₁ ∧ … ∧ c_j` 无解，`F` 本身未必 | 从 `F` 推出 `(¬c₁ ∨ … ∨ ¬c_j)`，**不是**空子句 |

## 4. 检查器的使用

```
build/rup_check   formula.cnf proof.rup                    # C++，快
build/rup_check   --ignore-deletions formula.cnf proof.rup # 纯 RUP 添加序列
build/rup_check   --assume "3 -7" formula.cnf proof.rup    # 检查 F ∧ x3 ∧ ¬x7 的反驳
python3 checker/rup_check.py [--explain] formula.cnf proof.rup   # 参考实现；--explain 打印每步的传播链
build/model_check formula.cnf solver_output.txt            # 检查 SAT 赋值
```

退出码：`0` 通过，`1` 拒绝，`2` 用法或输入错误。
