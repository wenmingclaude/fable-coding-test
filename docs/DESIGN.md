# 算法设计

读者假设：学过离散数学（命题逻辑、归纳法），没有系统学过 SAT 求解。
本文从一个具体例子出发，说明每个部件是为了解决什么问题而出现的。
正确性论证单独放在 [CORRECTNESS.md](CORRECTNESS.md)，实测数据在 [RESULTS.md](RESULTS.md)。

## 0. 一句话概括

求解器是一个 **CDCL（冲突驱动子句学习）** 求解器：

> 猜一个变量的值 → 推出所有必然的后果 → 如果撞墙，弄清楚"到底是哪几个猜测合起来导致撞墙"，
> 把这个教训写成一条新子句 → 退回去 → 继续。

每条"教训"都是原公式的逻辑推论，而且是一种特别容易验证的推论（RUP）。
把它们按顺序写进文件，就得到了一份任何人都能独立检查的不可满足性证明。
**搜索过程中积累的知识，和交给检查器的证明，是同一样东西。**

## 1. 从暴力枚举到"推出必然的后果"

```
(x₁ ∨ x₂) ∧ (¬x₁ ∨ x₃) ∧ (¬x₂ ∨ ¬x₃) ∧ (¬x₃ ∨ x₄)
```

暴力法枚举 2⁴ = 16 种赋值。但只要猜 `x₁ = 真`，第二个子句 `(¬x₁ ∨ x₃)` 里 `¬x₁` 已经为假，
要让它成立只能 `x₃ = 真`；于是 `(¬x₂ ∨ ¬x₃)` 逼出 `x₂ = 假`，`(¬x₃ ∨ x₄)` 逼出 `x₄ = 真`。
一次猜测带出三个结论，没有任何枚举。

这就是**单位传播**：一条子句只剩一个文字未定、其余全假时，剩下那个必须为真。
"猜测 + 单位传播 + 撞墙就回退换另一个值"是 1962 年的 DPLL 算法，
也就是本项目的**基线求解器** `baseline/dpll.cpp`。

### 怎样让传播变快：两个监视文字

传播是求解器里执行最频繁的操作（实测占 75% 以上的指令，见 RESULTS.md）。
朴素做法是每次赋值后扫描所有包含该变量的子句，绝大多数扫描都是白费的：一条有 20 个文字的子句，
在第 1 个文字变假时什么都推不出来。

关键观察：**一条子句只要还有两个"未被证伪"的文字，就既不是单位子句也不是冲突子句。**
所以每条子句只需"盯住"它的两个文字（监视文字）；只有当被盯的文字变假时才去看这条子句：

* 能在子句里找到另一个非假文字 → 改盯它；
* 找不到 → 另一个监视文字就是唯一的希望：它未赋值则被逼为真，它为假则是冲突。

回退时什么都不用做：被撤销的文字从"假"变回"未定"，监视关系依然合法。这是这个数据结构最漂亮的地方。

本实现在此基础上还有两个缓存局部性优化（都可以用开关关掉做对照）：

* **阻塞文字**（`--no-blocker`）：监视表项里额外存一个该子句的其他文字。如果它已经为真，子句已满足，
  连子句的内存都不必访问——监视表是连续数组，而子句散落在各处，少一次访问就是少一次缓存缺失。
* **二元子句内联**（`--no-inline-binary`）：二元子句 `(a ∨ b)` 的全部信息就是"a 假则 b 真"，
  直接存在监视表里，传播时完全不访问子句内存。

子句本身存放在一个连续的 `uint32_t` 数组（arena）里，用下标引用，头部两个字（长度、标志+LBD）。

## 2. 从失败中学习

DPLL 的问题是会反复犯同一个错误。设想搜索到很深的地方才发现：只要 `x₃ = 真` 且 `x₇ = 假`，
无论别的变量怎么取都会矛盾。DPLL 回退一层、换个无关变量的值，然后再一次走进同一个死胡同——
死胡同的真正原因（`x₃ ∧ ¬x₇`）从未被记录下来。

CDCL 的做法：撞墙时**分析冲突**。

### 蕴含图与冲突分析

每个被传播出来的文字都记着"是哪条子句逼出我的"（它的**原因子句**）。
从被证伪的子句出发，沿着原因子句往回走，就能找到一组文字，它们合在一起足以导致这次冲突。
这组文字全取反，就是一条新的子句——**学习子句**，意思是"这些条件不能同时成立"。

用逻辑的话说，每往回走一步，就是做一次**归结**（resolution）：

```
(A ∨ x)   (B ∨ ¬x)
───────────────────
      (A ∨ B)
```

从冲突子句开始，与"最近被赋值的那个文字"的原因子句归结，重复，直到子句里**只剩一个当前决策层的文字**为止。
这个停止点叫**第一唯一蕴含点（1UIP）**。停在这里的好处是：学到的子句在回退之后立刻变成单位子句，
直接把那个文字逼成相反的值——搜索被自动引向没试过的方向，不需要"翻转决策"这个概念。

### 非时序回退

学习子句 `(¬u ∨ l₁ ∨ … ∨ l_k)` 中，`u` 在当前层，其余文字在更早的层。
回退到其余文字中最深的那一层即可（而不是只退一层）：中间那些层的决策与这次冲突无关，全部跳过。

### 学习子句最小化（`--no-minimize`）

学习子句里的某个文字，如果它的原因子句中其他文字都已经在学习子句里（或者递归地满足这个条件），
它就是多余的，可以删掉。子句越短，将来能剪掉的搜索空间越大，证明也越短。
实现为蕴含图上的迭代式深度优先搜索（不使用递归，20 万变量的蕴含链不会爆栈），
并缓存"已知多余/已知不多余"的结论避免重复探索。

## 3. 证明从哪里来

到这里已经可以看出证明是怎么"免费"得到的。

**学习子句都满足 RUP 性质**：把学习子句的每个文字都假设为假，然后只做单位传播，一定会撞墙。
原因很直观——学习子句本来就是"沿着单位传播的原因子句往回走"得到的；把它的文字都设为假，
单位传播就会沿着同样的路径**往前**重新走一遍，最后撞上同一条冲突子句。

所以求解器只要在每次学到子句时把它写进文件（`proof_.add`，在这条子句被使用之前）。
检查器按顺序读每一条，做"取反 + 单位传播"的检查，通过就把它加入自己的子句库。

求解器最终报告 UNSAT 的时刻，是它**在没有任何猜测的情况下**（决策层 0）撞墙的时刻。
此时写出空子句；对检查器来说，空子句的 RUP 检查就是"什么都不假设，直接单位传播，必须冲突"。

需要额外写进证明的只有三处，都是为了让检查器的子句库与求解器保持同步：

1. 第 0 层被传播出来的文字，各写一条单位引理（这样即使它的原因子句后来被删除，检查器仍然知道它）；
2. 化简时把子句中已为假的文字去掉（先写新子句，再写 `d` 删除旧子句——顺序不能反）；
3. 子句被删除时写一行 `d`。

**证明与高性能如何共存**：写证明只是往缓冲区追加几个整数，不改变搜索路径。实测开销见 RESULTS.md。
求解器不使用任何"不是 RUP"的推理（例如有界变量消元、对称性破缺），
这是有意的取舍：这些技术能加速某些实例，但证明格式要升级到 DRAT，检查器也必须变复杂。

## 4. 往哪个方向搜索

### 变量选择：VSIDS（`--no-vsids`）

每个变量有一个活跃度。每次冲突分析中出现过的变量活跃度增加，且增量每次冲突放大 1/0.95 倍——
等价于旧的贡献按指数衰减。决策时选活跃度最高的未赋值变量（二叉堆）。
直觉：最近的冲突涉及哪些变量，问题的"硬核"就在哪里，先把它们定下来。

### 取值选择：初始相位与相位保存（`--phase=occ|0|1`、`--no-phase-saving`）

变量第一次被决策时取哪个值？默认取"它在原始子句中出现次数较多的那个符号"（`--phase=occ`）：
这个值能直接满足更多子句。这是一次性的 O(|F|) 统计，之后不再更新。

变量被回退时记住它刚才的值，下次再决策到它时沿用（相位保存）。回退往往只是为了修正一个局部错误，
其余部分的赋值很可能仍然是好的，不应该丢掉。

这两项的实测效果差别很大：初始相位在"先定答案再生成子句"的实例上效果显著，在其他实例上基本无影响；
相位保存在本项目的基准集上**没有**表现出收益。数据与讨论见 RESULTS.md。

### 重启（`--restart=ema|luby|none`）

搜索可能因为早期几个不幸的决策陷在没有希望的区域。重启 = 回退到第 0 层，但保留所有学习子句、活跃度和相位，
所以不是"从头再来"，而是"带着学到的东西重新排优先级"。

默认策略：维护学习子句 LBD（见下）的快、慢两个指数滑动平均；
最近学到的子句明显比长期平均差（快 > 1.1 × 慢）时重启。

### 稳定模式与目标相位（`--no-stable`、`--no-target-phase`）

频繁重启有利于证明 UNSAT，却不利于"沿着一个有希望的赋值走到底"找到解。
所以求解器在两种模式间交替（阶段长度几何增长）：**专注模式**用上面的快速重启；
**稳定模式**很少重启（Luby 序列 × 1024），并且决策取值优先使用"目标相位"——
迄今为止无冲突地走得最远的那个部分赋值。此外每隔一段时间把保存的相位重置为
初始值 / 取反 / 历史最佳 / 随机，跳出局部陷阱。

这部分是否值得，取决于实例，RESULTS.md 的消融表给出了数据。

## 5. 控制内存：子句库约简（`--no-reduce`）

学习子句无限增长会拖慢传播、耗尽内存。每条学习子句有一个质量指标 **LBD**
（其文字分布在多少个不同的决策层上；越小越"紧凑"，经验上越有用）。
每隔 2000 + 300k 次冲突做一次约简：

* 永久保留：二元子句、LBD ≤ 2 的子句；
* 暂时保留：上次约简以来在冲突分析中被用到过的子句、当前作为某个赋值原因的子句；
* 其余按（LBD 大、长度大）排序，删掉较差的一半。

被删除的子句是 `F` 的推论，删掉不改变公式的解；将来真需要可以重新学到。
被删除子句占用的 arena 空间在垃圾超过 25% 时通过整理回收（搬移子句、修正监视表和原因引用）。
内存压力大时（arena 超过预算的一半）约简频率提高；超过预算则放弃并输出 `s UNKNOWN`。

### 第 0 层化简（`--no-simplify`）

第 0 层确定的文字是永久事实。含有真文字的子句永远满足，可以删除；子句中的假文字可以去掉。
这在有大量单位子句或长传播链的输入上能大幅缩小子句库。

## 6. 增量求解（假设）

`solve(assumptions)` 把假设当作最先做的几个"决策"，每个假设占一个决策层。
学习子句是由 `F` 的子句归结得到的——决策（包括假设）从不作为前提参与归结——
所以**在任何假设下学到的子句都只依赖 `F`**，可以在不同查询之间安全复用。
查询之间被重置的只有赋值（回退到第 0 层）；启发式状态（活跃度、相位）保留，它们不影响正确性。

如果轮到某个假设 `a` 时它已经被传播成假，说明 `F` 加上前面的假设蕴含 `¬a`。
此时从 `¬a` 沿原因子句往回走到底，收集路上遇到的假设，就得到一个足以导致矛盾的假设子集（冲突核）。
对应的子句 `(¬a ∨ ¬a_{i1} ∨ …)` 是 `F` 的推论且满足 RUP，被写入证明流，供
`rup_check --assume` 验证（见 PROOF_FORMAT.md §3.5）。

返回的核是"充分的"，但不保证最小。

## 7. 没有做的事（以及原因）

| 技术 | 不做的原因 |
|---|---|
| 有界变量消元、阻塞子句消除等预处理 | 需要 DRAT 证明和模型重建，检查器与求解器都明显变复杂 |
| 异或约束的高斯消元 | 能让奇偶类实例从指数变多项式，但其推理不是 RUP |
| 对称性破缺、基数约束推理 | 同上；鸽巢问题对任何基于归结的求解器都是指数级的 |
| 局部搜索 | 对大规模"刚好可满足"的随机实例很有效，但不能证明 UNSAT，属于另一类求解器 |
| 多线程 | 超出本题范围 |

这些取舍的后果在 RESULTS.md 的"已知限制"里有对应的实测数据。
